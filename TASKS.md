## Этап 2: Аудиопоток, ASR и доставка событий в реальном времени (Дни 2-4)
**Цель:** Прием аудио из LiveKit, распознавание речи (Soniox + fallback Whisper Groq), генерация транскрипта и доставка клиентам через SSE.

- [x] **2.1. Единый интерфейс и адаптеры ASR**
  - [x] Описать Protocol `AsrStream` и модели событий `AsrEvent` (`partial`, `final`).
  - [x] Реализовать клиент `backend/app/asr/soniox_stream.py`:
    - WebSocket стриминг PCM16 (16kHz, mono).
    - Передача `language_hints`, `expected_terms`, включение диаризации.
    - Автореконнект с экспоненциальной задержкой (0.5, 1, 2, 4 с, до 5 попыток).
    - Кольцевой аудио-буфер на 30 секунд для предотвращения потери слов при обрыве.
  - [x] Реализовать резервный ASR `backend/app/asr/groq_whisper.py`:
    - Нарезка на чанки 15-30 с (Silero VAD / silence split).
    - Запросы к Groq Whisper Large v3 Turbo, склейка перекрытий по словам.
    - Переключение на Groq после 5 неудач Soniox.
- [x] **2.2. Нормализация транскрипта**
  - [x] Реализовать `backend/app/asr/normalize.py`:
    - Склейка токенов в предложения по паузам ≥ 0.8 с.
    - Публикация эфемерных событий `transcript.partial` (только pub/sub, без сохранения в БД и без `seq`).
    - Сохранение сегментов в `transcript_segments` и публикация `transcript.final` (с `seq`).
- [x] **2.3. Медиа-бот LiveKit**
  - [x] Реализовать `backend/app/media/livekit_bot.py`:
    - Подключение к комнате LiveKit как бот-участник.
    - Подписка на аудиотрек через `rtc.AudioStream`.
    - Генерация `teacher_token` для входа преподавателя.
    - Управление жизненным циклом бота через Redis Stream `stream:bot-commands`.
- [x] **2.4. SSE-стриминг событий клиентам**
  - [x] Реализовать `POST /v1/lessons/{id}/sse-token` (короткоживущий токен для EventSource).
  - [x] Реализовать `GET /v1/lessons/{id}/events`:
    - Поддержка авторизации через query `?token=` и `Authorization: Bearer`.
    - Heartbeat `: ping` каждые 15 секунд.
    - Возобновление по `Last-Event-ID` или `?after_seq=N`.
    - Отдача пропущенных событий из БД (`seq > N`), затем прозрачное переключение на Redis pub/sub без дыр и дублей.
- [x] **2.5. Тестирование Этапа 2**
  - [x] Unit-тесты нормализации токенов и пауз.
  - [x] Тест переподключения к ASR с кольцевым буфером (ноль потерь слов).
  - [x] Интеграционный тест SSE с проверкой склейки истории и живого потока.
  - [x] **Критерий:** Бот транслирует аудио, в SSE поступают `transcript.partial` (задержка p95 ≤ 2.5 с) и `transcript.final`.

## Этап 3: Детекция кадров, VLM-анализ и серверный рендер (Дни 4-6)
**Цель:** Захват видео, детекция смены слайда/доски, отбор информативных кадров через Gemini VLM и серверная отрисовка аннотаций.

  - [x] Реализовать подписку на видеодорожку в `backend/app/media/video_pipeline.py`:
    - `rtc.VideoStream(track)` с ограничением `FRAME_SAMPLE_FPS=1`.
    - Поддержка настройки `roi` (обрезка области доски).
- [x] **3.2. Алгоритм детекции слайдов и доски**
  - [x] Реализовать `backend/app/frames/detector.py`:
    - Расчет `diff` по градации серого и `imagehash.phash`.
    - Конечный автомат состояний `changing` / `stable`.
    - Фильтры: размытие (дисперсия Лапласа < `MIN_LAPLACIAN_VAR`), дубликаты (pHash ≤ 4 к последним 8 кадрам), антиспам (`MIN_FRAME_GAP_SEC=4`).
    - Логика накопления рукописного текста на доске (пауза ≥ 2 с, прирост площади ≥ 3%).
    - Сохранение кадра-кандидата в S3 (`.webp`, q90) и запись в БД (`status='candidate'`).
    - Публикация сообщения в Redis Stream `stream:frames`.
- [x] **3.3. VLM-адаптер (Gemini 3.5 Flash-Lite)**
  - [x] Описать Pydantic-схему `FrameAnalysisOutput` (keep, informativeness, kind, title, ocr_markdown, description, annotations, duplicate_of_previous).
  - [x] Реализовать `backend/app/ai/providers/gemini.py` для мультимодального анализа:
    - Подача кадра (≤ 1280px JPEG), контекста последних 60 с транскрипта и темы урока.
    - Настройка `thinking_level=minimal`, строгая валидация JSON-схемы.
    - Цепочка отказоустойчивости: `gemini-3.5-flash-lite` → `gemini-3.6-flash` → `VLM_FALLBACK_MODEL`.
    - Трекинг стоимости и логирование в `ai_calls`.
- [x] **3.4. Постобработка и серверный рендер аннотаций**
  - [x] Реализовать `backend/app/frames/render.py`:
    - Валидация нормализованных координат `box_2d` (0-1000) и фильтрация по площади.
    - Отрисовка Pillow: контрастная рамка, кружок-бейдж с номером, стрелка `point_2d`, подсветка `highlight`.
    - Разрешение коллизий: сдвиг перекрывающихся бейджей, шрифт Noto Sans.
    - Сохранение `frames/{id}_annotated.webp` в S3.
    - Перевод статуса кадра в `selected` (или `rejected` при низком скоре) и публикация `frame.selected`.
- [x] **3.5. Воркер анализа кадров (`ai-worker`)**

- [x] **3.6. Тестирование Этапа 3**

  - [x] Реализовать `POST /v1/lessons/{id}/process` (старт обработки).
- [x] **5.2. Сервис `file-processor`**
  - [x] Реализовать воркер `backend/app/workers/file_processor.py`:

    - Асинхронный ASR: клиент `backend/app/asr/soniox_async.py` (отправка файла, получение токенов, сохранение через общий `asr/normalize.py`).
