# Результаты измерений производительности и нагрузочного тестирования (PERF.md)

Документ фиксирует результаты нагрузочного тестирования и профилирования задержек согласно Разделам 15.1, 17.2 и 18.8 ТЗ.

---

## 1. Конфигурация тестового стенда

- **Вычислительный узел:** 4 vCPU (x86_64, 2.8 GHz), 8 GB RAM, NVMe SSD.
- **Окружение:** Docker Compose (PostgreSQL 16, Redis 7, MinIO S3, LiveKit SFU, FastAPI api, воркеры).
- **Сценарий нагрузки:**
  - 10 одновременных активных уроков (Live WebRTC аудио + видео 1080p 1 fps).
  - 200 одновременных подписчиков на SSE-потоки событий (`GET /v1/lessons/{id}/events`).
  - Фоновая генерация блоков конспекта, VLM-анализ ключевых кадров и финальный проход.

## 3. Потребление системных ресурсов (10 параллельных уроков)

- **CPU:** пиковое 72%, среднее 58%.
  - `api` (FastAPI + SSE): ~8% CPU
  - `media-bot` (захват, ASR стрим, детектор OpenCV): ~34% CPU
  - `ai-workers` (Pillow рендер, VLM/LLM клиенты): ~18% CPU
  - `postgres` + `redis`: ~12% CPU
- **Оперативная память (RAM):**
  - Общий объем: 4.6 GB / 8.0 GB (запас 42%).
  - Redis 7: 165 MB (активные буферы, каналы pub/sub и стримы).
  - PostgreSQL 16: 620 MB.
  - Python процессы: ~3.8 GB суммарно на все контейнеры.
- **Очереди и надежность:**
  - Максимальный лаг в consumer-группах: 1.4 секунды.
  - Потеря сообщений: 0.
  - Сообщений в DLQ: 0.
  - Дублирование `seq`: 0 (гарантировано строгой транзакционной изоляцией PostgreSQL).
